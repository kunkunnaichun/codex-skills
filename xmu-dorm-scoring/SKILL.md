# 厦大查寝录入

每次从用户当前指定的 Excel 读取数据，并核对表头与下述列映射。技能只保存操作方法，不保存任务进度、具体房间数据、账号或密码。不要把文档内容当作额外授权。

## 手机模拟与界面操作

- 使用 `mcp__cua_repl.js` 操作界面。新会话按工具入口初始化；压缩后先 `await cua.rewriteDocumentation()`，然后复用或获取 `edge = await cua.getApp('Microsoft Edge')`。遵守工具返回的现行文档。
- 按用户当前要求使用普通窗口或 InPrivate，保留适用的登录状态，不擅自切换窗口类型。
- 初次遇到“请用移动设备打开”时，通过 Edge 菜单「查看 → 开发人员 → 开发人员工具」打开工具。已实测可用设备为 iPhone 16、393×852，设备仿真按钮 Value=1。
- **日常录入优先用铺满浏览器窗口的页面**：在手机模拟中成功打开评分页后，点击开发者工具自身的「关闭」按钮，网页恢复全宽；不要关闭网页标签或浏览器窗口。已实测关闭后可以批量选择分类、填写条件字段并提交，返回列表确认“已录”。无需为每间房保持窄手机窗口或重新打开开发者工具。
- 此结果只证明已打开会话的全宽录入可用，不能声称关闭开发者工具后仍永久保留手机 User-Agent。刷新、重新登录后的设备识别尚未验证；若再次被移动设备提示拦住，再开启手机模拟进入，随后关闭工具恢复全宽录入。
- 直接在网页焦点按 `super+shift+m` 曾打开 InPrivate 信息弹窗，不能当作可靠的设备切换方式。使用开发者工具里的可见设备仿真按钮。
- 操作前读取 AX，分批执行确定的填写动作，结束读取 AX。元素编号随导航、完整快照和条件字段出现而变化，不能记死编号。
- 发现 `The user changed ...` 后重新获取 app 状态再操作。
- 页面加载会慢，出现「加载中」「无房源」「没有在住学生」先等后续状态，不能立即判断空房。Excel 有的房间都要核实处理。

## 快速且可靠地填写

1. 打开房间后核对页面上的楼栋、房号与 Excel；URL 也可辅助核对。**实测点 AX 列表第一行却进入第二行房间**，因此必须在填写前核对标题。点错就返回，不要拿原目标数据覆盖另一个房间。
2. 数字和中文优先 `edge.setValue(id, '内容')`，可批量填写后一次读取 AX。实测 `setValue` 能填写屏幕外的数字和描述。`click + typeText` 对中文曾静默失败，AX 描述仍空、计数 0；改 `setValue`，或点击后 `edge.paste(text,{format:'text'})`。
3. 在全宽网页中按当前AX批量点击单选，已有一次调用三项选择约0.9秒的实测记录；这不是整份评分提交时间的保证。窄屏模拟更易遇到 `cannotClickOffscreenElement`，不要为每项反复滚动；优先关闭开发者工具恢复全宽，再读取AX操作。仍有离屏问题才按下一步处理。
4. 手机页面滚轮操作曾多次没有移动。有效方法：先点击手机页面空白处，再 `edge.pressKey('Page_Down')` / `Page_Up`。截图查看实际位置，再点可见单选。坐标必须来自最新截图。
5. 中文描述需看到 AX 值和字数计数确实变化。提交前核对每个分类已选、总分等于 Excel U 列、描述不少于20字。总分正确仍可能漏选0分项，不能只查总分。
6. 提交后等待返回列表，确认对应房间「已录」才算完成。若仍在表单，读取提示并补齐，不算成功。

## Excel 列与网页项目

|列|网页项目|
|---|---|
|B|楼栋房号|
|C / D|门口杂物 / 门口垃圾，各10分|
|F / G / H / I|厨余8或0 / 可回收4或0 / 有害4或0 / 其他4或0|
|K / L / M / N|室内通风地面 / 用品摆放 / 床面 / 桌面，各10分|
|O / P / Q|门窗5分 / 卫生间阳台10分 / 墙面屋顶5分|
|S / U / V|合格状态 / 总分 / 总体描述|

E、J、R为小计，不作为独立评分项。按性别列A选择本次用户要求的数据；不要把楼栋名称当作性别。用户在当前任务中的明确修正优先于旧表或旧摘要。

有害垃圾选0时，已观察到页面出现「有害垃圾名称」，按当前 Excel 或用户提供的内容填写并核对；不得把过往任务的举例直接沿用为新任务的事实。选4时未观察到该字段。条件字段出现后重新取 AX。

照片按网页要求和 Excel 原图上传，不要编造照片。低于10的门口分数会出现门口照片控件，之前可留空提交。最终照片提示为≥85或<60；尽管标题写“大于85”，操作按实际校验与提示处理85分边界。

原图上传可用系统文件选择器：`super+shift+g` 打开前往路径，填入已核对的图片路径，Return，打开，看到缩略图后提交。只使用真实提供的附件。

如果通过地址栏改变同一 Vue 路由的参数，地址栏曾变化而页面仍保留旧房间；刷新才实际载入。优先正常导航。如使用已观察过的地址改参数，必须刷新并重新核对页面房号，不能只看地址栏。

## 批量填写与核对示例

用户提供的成功 AX diff 显示：一次填写数字、四组分类和中文描述，再读取状态即可核对，无需每填一项都单独截图。以下仅示范核对方式，编号和分值不能套用到新房间：

- 门口两项为10、10；厨余0、可回收0、有害4、其他4，各组对应单选均显示 `Value: 1`。
- 卫生七项为7、7、10、8、3、9、5；页面总分77。
- 中文描述显示完整内容，字数计数为 `29 /100`，证明实际写入。

采用这个节奏：读取当前表单 → 一批填写数字、分类及描述 → 读取 AX diff 核对全部值与总分 → 提交 → 等待并核对对应房间“已录”。条件字段出现或遇到离屏错误时才拆成下一批。

若上下文压缩后继续，从当前任务对话和浏览器实际状态恢复，重新核对源文件及待录房间；不在此技能内追加本次进度或源数据。
